## FORM

Canonical static pattern:

```baselscript
SCENE=1 title="Example"

SECTION init
    draw form=main_form
END

FORM main_form
    tile=text text="Name"
    tile=input id=#name
    tile=button text="OK" sec=save
END

SECTION save
    message #name
END

END SCENE
```

Common FORM tiles observed repeatedly include:

```text
text
input
button
property
prop
image
checkbox
radiobutton
seekbar
spinner
switch
togglebutton
```

Do not assume every tile accepts every common parameter.

## LIST

Static LIST pattern:

```baselscript
LIST list1
    tile=file id=example_person
    tile=title text="People"
    tile=item id=#first_name
    tile=button text="<" act=back
END
```

CURRENT special declaration:

```baselscript
LIST view <name>
```

`view` is a modifier, not the LIST name.

## Dynamic LIST

Confirmed lifecycle:

```baselscript
clear list_view=ccc
create tile=file id=dir_list dir=APPDIR/MYDATA/temp
create tile=title text="FILES"
create tile=item1 id=#file_name
call list=ccc
```

A runtime-created LIST does not require a static `LIST <name>` declaration.

## MENU

Static:

```baselscript
MENU mainmenu
    tile=item text="Settings" scene=setting
    tile=item text="Back" section=back
END
```

Dynamic:

```baselscript
clear menu=m2
create tile=title text="menu 2"
create tile=item1 text="option" sec=e11
call menu=m2
```

Dynamic MENU is CURRENT runtime syntax. A validator build that fails to collect the literal runtime-created name is a validator synchronization defect, not proof that the syntax is invalid.

## DIALOG

Use real DIALOG tile patterns. Do not invent a generic dialog API.

Example:

```baselscript
DIALOG input_dialog
    tile=title text="Enter value"
    tile=input1 id=#value
    tile=button1 text="OK" act=save
END
```

## Event targets

Observed CURRENT event target spellings include:

```text
sec= / section=
act= / action=
scene= / sce=
script= / scr=
```

Preserve working project style. Do not invent additional aliases.

## Common parameter vocabulary

Frequently observed:

```text
id text x y w h c bg s sty style g gravity sec act scene script dir visible
```

This is descriptive, not universal.

## Generation rules

- Prefer static UI when runtime construction is unnecessary.
- Use `clear` + `create tile=...` only for genuinely dynamic UI.
- Keep logic in SECTION/ACTION blocks.
- Do not invent tile types or parameters from HTML, Android, WPF, Flutter, or another UI toolkit.
