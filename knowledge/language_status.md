# BaselScript Language Status

## Purpose

This file defines how AI systems must interpret the current BaselScript language sources.

## Source authority

When sources disagree, use this precedence:

1. confirmed current runtime/regression evidence
2. current `.def` files
3. generated `language/baselscript-language.json`
4. current knowledge status files
5. repeated real `.script` corpus usage
6. rare corpus usage
7. historical/review candidates

The `.def` files are the formal language contract.
`baselscript-language.json` is a generated machine-readable snapshot of that contract.
Regression/runtime evidence can expose a stale or incorrect definition and therefore has higher
authority until the contract is synchronized.

Do not silently promote rare or historical syntax to CURRENT.

## LEGACY

LEGACY syntax may still occur in older scripts or documentation but should not be generated for new
scripts unless explicitly requested.

## EXPERIMENTAL / NOT STABLE

Do not generate these as normal BaselScript syntax unless the user explicitly requests experimental
work:

- `SWITCH / CASE`
- SECTION parameters
- LOCAL scope
- user-defined FUNCTION syntax
- TRY / CATCH

A previous SWITCH experiment was rolled back.

## Platform notes

The standalone command:

```baselscript
select
```

is CURRENT.

On Windows it opens the native file picker and returns the selected file and directory.

On Android it uses the system document picker. The selected document is made accessible to
BaselScript through an internal temporary copy before execution resumes.

Do not assume unrestricted direct access to Android public storage.
