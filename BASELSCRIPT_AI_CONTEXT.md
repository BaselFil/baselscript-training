# BaselScript AI Context

This is the canonical entry point for AI systems working with BaselScript.

## Required loading sequence

Before generating, reviewing, explaining, or modifying BaselScript:

1. read `manifest.json`
2. read every file marked `required`
3. use the source authority below
4. do not invent syntax that is not supported by the current reference

## Source authority

```text
confirmed current runtime/regression
> current language/*.def
> generated language/baselscript-language.json
> current knowledge/*.md
> repeated real script corpus
> rare corpus evidence
> historical/review examples
```

The `.def` files are the formal contract.
`baselscript-language.json` is generated by the interpreter and must not be hand-edited.

## Hard generation rule

Do not invent:

- actions
- functions
- parameters
- blocks
- condition operators
- closing keywords
- CALL target families
- graphics tiles
- CHART syntax
- platform APIs

If a construct cannot be confirmed, label it unverified instead of guessing.

## Explicitly removed standalone actions

Do not generate:

```text
db_current
db_path
db_exists
open
grid
pdf
mail
vibrate
```

Use standalone `select` for the current file-picker workflow.

Android notification vibration is a notification feature and is not evidence for a standalone
`vibrate` action.

## Known validator issue

Dynamic MENU is valid CURRENT runtime syntax:

```baselscript
clear menu=m2
create tile=title text="menu 2"
create tile=item1 text="option" sec=e11
call menu=m2
```

The currently installed validator build can still report that the dynamic MENU does not exist.
Treat this as an open Validator/build synchronization defect, not as invalid language syntax.
